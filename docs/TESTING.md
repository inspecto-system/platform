# Стратегия тестирования Inspecto

> Правила оформления и пороги покрытия — [CODE_QUALITY.md](CODE_QUALITY.md). Здесь — что и как проверяется, ключевые тест-кейсы и журнал результатов.

## 1. Уровни тестирования

| Уровень | Что проверяется | Инструменты | Где запускается |
|---|---|---|---|
| Unit | Бизнес-правила в изоляции | JUnit 5, Mockito, `go test`, Vitest, pytest, MockK | CI каждого репозитория |
| Интеграционные | Сервис с настоящими PostgreSQL и SeaweedFS | Testcontainers, testcontainers-go | CI каждого репозитория |
| Контрактные | Ответы сервисов соответствуют OpenAPI | Валидатор OpenAPI в интеграционных тестах | CI сервисов |
| API (сквозные) | Сценарии через nginx на поднятом compose | REST Assured (Kotlin) | CI `platform` вручную и по расписанию |
| UI Web | Компоненты и сценарии в браузере | React Testing Library, Playwright | CI `web` |
| UI Android | ViewModel, экраны, навигация | JUnit, Turbine, Compose UI Test, MockWebServer | CI `android` + ручная проверка на устройстве |
| Безопасность | OWASP Top 10, IDOR, токены | Интеграционные тесты, OWASP ZAP baseline, CodeQL, сканеры зависимостей | CI + CP5 |
| PDF | Корректность и читаемость отчёта | Извлечение текста (pdftotext/pdfcpu), проверка шрифтов и размера | CI `report-service` |
| ML | Качество модели и эквивалентность экспорта | pytest, фиксированный тест-набор | CI `ml` + отчёт эксперимента |
| Ручное | Главный демонстрационный сценарий на устройстве | Чек-лист CP | Каждая контрольная точка |

## 2. Ключевые тест-кейсы

### 2.1. Сравнение осмотров (ADR-004)

Табличный (параметризованный) тест: для каждого дефекта задаются наблюдения в A и B, ожидается состояние.

| № | Наблюдение в A | Наблюдение в B | Ожидаемое состояние |
|---|---|---|---|
| CMP-01 | — | `OPEN` | Новый |
| CMP-02 | `OPEN` | `RESOLVED` | Устранённый |
| CMP-03 | `OPEN` | `OPEN` | Оставшийся |
| CMP-04 | `OPEN` | — | Не проверен |
| CMP-05 | `RESOLVED` | `OPEN` | Новый, `reopened = true` |
| CMP-06 | `RESOLVED` | — | Не входит в сравнение |
| CMP-07 | Осмотры разных объектов | — | `400 VALIDATION_ERROR` |
| CMP-08 | `base` позже `target` | — | `400 VALIDATION_ERROR` |
| CMP-09 | Замена фото без изменения статуса | — | Статус не меняется |
| CMP-10 | Чужой осмотр | — | `404 NOT_FOUND` |

Дополнительно проверяются суммы `summary` и разбивки по категориям и серьёзности.

### 2.2. Безопасность и доступ

| № | Сценарий | Ожидание |
|---|---|---|
| SEC-01 | Запрос к любому ресурсу другого пользователя (объект, осмотр, дефект, фото, отчёт) | `404` для каждого endpoint (параметризованный тест) |
| SEC-02 | Истёкший, подделанный (другой ключ), с `alg=none`, с чужой аудиторией JWT | `401` |
| SEC-03 | Повторное использование refresh-токена | `401`, всё семейство токенов отозвано |
| SEC-04 | 6 неудачных входов подряд | `423 ACCOUNT_LOCKED` |
| SEC-05 | Пользовательский токен на `/internal/**` | `401` |
| SEC-06 | INSPECTOR меняет системную категорию | `403` |
| SEC-07 | `<script>` в описании дефекта | Сохраняется как текст; в Web и PDF отображается экранированным |
| SEC-08 | Refresh в Web без `X-CSRF-Protection` | `403` |
| SEC-09 | Ответы содержат заголовки безопасности (HSTS, CSP, `X-Content-Type-Options`, …) | Проверка в сквозных тестах |
| SEC-10 | Логи после сценария входа не содержат пароль и токены | Проверка вывода логов |

### 2.3. Фотографии

| № | Сценарий | Ожидание |
|---|---|---|
| PH-01 | JPEG, PNG, WebP допустимого размера | `201`, три варианта в SeaweedFS, EXIF удалён |
| PH-02 | Файл `.jpg` с содержимым PDF/EXE | `400 UNSUPPORTED_MEDIA_TYPE` |
| PH-03 | Файл больше лимита | `413 IMAGE_TOO_LARGE` (до чтения тела целиком) |
| PH-04 | «Бомба распаковки» (огромные размеры при малом файле) | `400 IMAGE_DIMENSIONS_TOO_LARGE` без декодирования |
| PH-05 | Превышен лимит фото на наблюдение | `400 PHOTO_LIMIT_EXCEEDED` |
| PH-06 | Повтор с тем же `Idempotency-Key` | Тот же `id`, без дубликата |
| PH-07 | Неприкреплённое фото старше 24 ч | Удалено из базы и SeaweedFS |
| PH-08 | SeaweedFS недоступен | `503`, в базе нет «висячей» записи |

### 2.4. PDF-отчёты

| № | Проверка |
|---|---|
| PDF-01 | Документ открывается, число страниц ≥ 1, текст извлекается |
| PDF-02 | Кириллица отображается (шрифт встроен) |
| PDF-03 | Есть название объекта, дата осмотра, все дефекты и их фото |
| PDF-04 | Размер файла ≤ лимита для осмотра с 50 фото |
| PDF-05 | Карточка дефекта не разрывается между страницами |
| PDF-06 | Пользовательский HTML в описании выводится как текст |
| PDF-07 | Рендеринг не обращается к внешним адресам (Gotenberg без сети) |
| PDF-08 | Отказ Gotenberg → повторы → `FAILED` с кодом ошибки |

### 2.5. Взаимодействие сервисов

| № | Сценарий | Ожидание |
|---|---|---|
| INT-01 | Остановлен ml-service | Создание дефекта проходит, подсказка пустая |
| INT-02 | Остановлен media-service при привязке фото | `503`, транзакция core откатилась |
| INT-03 | Остановлен core при загрузке фото | `503` |
| INT-04 | Удаление объекта | В базах и SeaweedFS не осталось данных объекта (после обработки outbox) |
| INT-05 | Неизвестный `kid` в JWT после ротации ключа | Go-сервис перезагружает JWKS и принимает токен |

## 3. Тестовые данные

- Генерируются фабриками в тестах; фиксированные идентификаторы и время.
- Тестовые изображения — синтетические или собственные снимки автора без персональных данных; хранятся в `testdata/`.
- Реальные персональные данные в тестах и репозиториях запрещены.

## 4. Критерии прохождения контрольной точки

- Все автоматические проверки CI зелёные во всех затронутых репозиториях.
- Пороги покрытия выполнены (CODE_QUALITY.md, §5).
- Ручной сценарий CP пройден и зафиксирован в журнале ниже.
- Нет открытых дефектов с серьёзностью «высокая» и уязвимостей уровня High/Critical.
