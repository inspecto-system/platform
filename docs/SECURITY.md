# Безопасность Inspecto

> Меры защиты по уровням системы. Угрозы и их связь с мерами — [THREAT_MODEL.md](THREAT_MODEL.md). Ориентиры: OWASP Top 10 (2021), OWASP API Security Top 10 (2023), OWASP ASVS, рекомендации по безопасной разработке для Java, Go, Kotlin и TypeScript.
> Статус: спроектировано (CP0). Столбец «Проверка» в разделе 11 заполняется по мере реализации.

## 1. Принципы

1. Безопасность учитывается с первого коммита каждого компонента, а не перед сдачей.
2. Минимальные привилегии: у каждого сервиса и пользователя СУБД — только необходимые права.
3. Запрет по умолчанию: доступ к ресурсу разрешается только после явной проверки прав.
4. Глубокая защита: nginx, сервисы и база проверяют входные данные независимо.
5. Критические и высокие уязвимости устраняются до слияния; известные средние — до релиза CP7.

## 2. Аутентификация

| Мера | Реализация |
|---|---|
| Хранение паролей | Argon2id (параметры не ниже рекомендаций OWASP Password Storage Cheat Sheet) |
| Политика паролей | Длина ≥ 10; проверка по списку распространённых паролей; без требований к составу символов (NIST SP 800-63B) |
| Access-токен | JWT RS256, 15 минут, проверяются `iss`, `aud`, `exp`, `nbf`; разрешён только алгоритм RS256 (защита от `alg=none` и подмены алгоритма) |
| Refresh-токен | 256 бит случайности, 30 дней, хранится только SHA-256, ротация при использовании, повторное использование отзывает семейство |
| Ключи подписи | Закрытый ключ — секрет окружения core; `kid` для ротации (`CORE_JWT_KEY_ID`); без настроенного ключа (только разработка) core создаёт временный ключ при каждом запуске, его `kid` — отпечаток RFC 7638, поэтому media-service перечитывает JWKS сама; открытый ключ — JWKS |
| Смена пароля, удаление аккаунта | Требуют текущий пароль; отзывают все refresh-токены |
| Защита от перебора | nginx: 5 запросов/мин с IP на `/auth/login` и `/auth/register`; блокировка учётной записи на 15 мин после 5 неудач; одинаковый ответ для неизвестного email и неверного пароля |
| Перечисление пользователей | Регистрация с занятым email возвращает `409` только после успешной проверки rate limit; время ответа входа выравнивается (хеширование выполняется и для несуществующего пользователя) |

## 3. Авторизация (RBAC + права на ресурс)

- Роли: `ADMIN`, `INSPECTOR`, `CLIENT` (ADR-009). Проверка роли — декларативно на endpoint.
- **Каждый** запрос к ресурсу проверяет владение (или выданный доступ) в сервисном слое, а не только в контроллере; идентификатор пользователя берётся только из токена, никогда из тела запроса.
- Чужой ресурс — `404` (не раскрывается существование).
- media-service и report-service проверяют права через core (`/internal/v1/access/...`) с кешем положительных ответов не дольше 60 с.
- Массовое присваивание (mass assignment) исключено: входные DTO содержат только разрешённые поля; `ownerId`, `role`, `status` клиент не задаёт.
- Параметризованные IDOR-тесты для каждого endpoint (TESTING.md, SEC-01).

## 4. Защита API от распространённых атак

| Атака | Меры |
|---|---|
| SQL Injection | Только параметризованные запросы (JPA/JPQL с параметрами, pgx с плейсхолдерами); запрет конкатенации SQL (правило статического анализа); пользователь СУБД без прав DDL |
| XSS | API возвращает только JSON; React экранирует вывод, `dangerouslySetInnerHTML` запрещён правилом ESLint; строгая CSP; в PDF — автоматическое экранирование `html/template` |
| CSRF | Access-токен передаётся в заголовке, а не в cookie; refresh-cookie `SameSite=Strict` + обязательный заголовок `X-CSRF-Protection` |
| SSRF | Сервисы не загружают ресурсы по URL из запросов пользователей; Gotenberg во внутренней сети без выхода в интернет и с `--chromium-allow-list=^file:///tmp/.*` (Chromium может читать только файлы текущей конвертации), JavaScript в Chromium отключён; изображения встраиваются в HTML заранее; адреса внутренних сервисов — только из конфигурации |
| Brute force | Rate limiting nginx + блокировка учётной записи (раздел 2) |
| Неограниченное потребление ресурсов | Лимит тела запроса на nginx и в сервисах; лимит пикселей изображения до декодирования; пагинация с максимумом 100; таймауты; ограничение параллельных воркеров PDF |
| Загрузка вредоносных файлов | Проверка типа по сигнатуре; перекодирование изображения (вредоносная полезная нагрузка не сохраняется); файлы выдаются с правильным `Content-Type` и `X-Content-Type-Options: nosniff` |
| Path traversal | Ключи объектов SeaweedFS формируются сервисом из UUID, имена файлов пользователя не используются |
| Десериализация | Только JSON с явными DTO; запрет полиморфной десериализации Jackson |
| Раскрытие информации | Ответы об ошибках без стеков и SQL; `server_tokens off` в nginx; актуаторы Spring закрыты |

## 5. Секреты

- Секреты (пароли СУБД, ключи SeaweedFS, закрытый ключ JWT, секреты сервисных клиентов) передаются только через переменные окружения или docker secrets; в репозиториях — только `.env.example` без значений.
- Gitleaks в CI каждого репозитория и pre-commit-хук (рекомендуется).
- Репозитории публичные (ADR-015): обнаруженный в истории секрет считается скомпрометированным и немедленно перевыпускается.
- Секреты не пишутся в логи; логгеры маскируют поля `password`, `token`, `secret`, `authorization`, `cookie`.

## 6. Базы данных

| Мера | Реализация |
|---|---|
| Разграничение прав | Пользователи `*_migrator` (владельцы схем, DDL — только при миграции) и `*_app` (только DML на свою базу); `REVOKE ALL ON DATABASE` для `PUBLIC`; сервис не видит чужие базы |
| Шифрование соединений | TLS между сервисами и PostgreSQL (`sslmode=verify-full` в эксплуатации, `require` в разработке) |
| Сетевой доступ | PostgreSQL только во внутренней сети `data`, порт наружу не публикуется (в разработке — только на `127.0.0.1`) |
| Резервное копирование | Ежедневный `pg_dump` каждой базы и зеркалирование бакетов SeaweedFS; хранение 14 дней с ротацией; копии шифруются |
| Восстановление | Скрипт восстановления на чистое окружение; проверка восстановления — задача T-507 и перед CP7 |
| Целостность | Ограничения `CHECK`, `UNIQUE`, внешние ключи внутри базы; SHA-256 для файлов |

## 7. Файлы: фото и PDF

- SeaweedFS недоступен снаружи; бакеты приватные; у каждого сервиса свои учётные данные с доступом только к своему бакету.
- Выдача файлов только через media-service и report-service с проверкой прав на каждый запрос; прямые или долгоживущие ссылки клиентам не выдаются.
- EXIF (включая геолокацию) удаляется при загрузке.
- `Cache-Control: private` и `Content-Disposition: attachment` для PDF.

## 8. Межсервисное взаимодействие

- Внутренние endpoints (`/internal/**`) не маршрутизируются nginx и требуют сервисный JWT с `aud=inspecto-internal`; пользовательские токены там не принимаются.
- Сервисы находятся во внутренних сетях docker (`internal: true`); наружу опубликован только nginx.
- В эксплуатационной конфигурации (этап расширения) — TLS между сервисами.

## 9. Персональные данные и удаление

- Персональные данные: email, ФИО, адреса объектов, фотографии помещений. Обработка ориентирована на требования Федерального закона № 152-ФЗ «О персональных данных» (минимизация, цели обработки, удаление по запросу).
- Минимизация: собираются только поля, нужные для работы; геоданные из фото удаляются.
- Пользователь может удалить объект или аккаунт (`DELETE /properties/{id}`, `DELETE /users/me`): записи удаляются транзакционно, файлы — заданиями outbox с повторами до успеха (ADR-018).
- Удалённые данные исчезают из резервных копий после ротации (14 дней).
- В логах нет персональных данных, кроме идентификаторов пользователя (UUID).

## 10. Транспорт и браузер

| Мера | Значение |
|---|---|
| HTTPS | TLS 1.2+ (предпочтительно 1.3), редирект с HTTP; в разработке — самоподписанный сертификат |
| HSTS | `max-age=31536000; includeSubDomains` |
| CSP | API (nginx): `default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'`. Web: `default-src 'self'; img-src 'self' blob: data:; object-src 'none'; frame-ancestors 'none'; base-uri 'self'` (уточняется при реализации Web) |
| Прочие заголовки | `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY` (nginx, все ответы), `Permissions-Policy: camera=(), geolocation=()` для Web |
| CORS | Разрешён только origin веб-приложения; без `*`; `Access-Control-Allow-Credentials` только для `/api/v1/auth/**` |
| Android | `usesCleartextTraffic=false`, токены в DataStore с ключом Android Keystore, `allowBackup=false` для данных с токенами, без логирования тел запросов в release-сборке |
