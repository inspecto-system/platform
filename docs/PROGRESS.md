## Где остановилась работа

Срез 2 и серверная часть CP3 слиты. Контракт `api-v0.6.0`: сравнение осмотров по состояниям «на момент A / B» (T-301, уточнение ADR-004), статистика объекта (T-302), удаление аккаунта со всеми данными и файлами (T-303; сквозной сценарий проверяет базы и SeaweedFS). Android (срез 2): проведение осмотра (T-306), повторный осмотр с явной отметкой «остался / устранён» (T-403), камера и очередь загрузки фото (T-307), черновики без сети (T-308). Всё проверено на эмуляторе API 37 против core и media из compose.

CP4: report-service (T-401, T-402, ADR-026) — задания в очереди, PDF через Gotenberg со встроенными шрифтами, бакет `reports`, `report.yaml` 0.5.1 (тег `api-v0.7.1`). Удаление объекта и аккаунта удаляет и отчёты (outbox core). report-service в compose (профиль `apps`); сквозной сценарий заказывает и скачивает PDF и проверяет, что после удаления не осталось ни записей, ни байтов в `reports`. Android: отчёты (T-404) и сравнение двух осмотров (T-405). Всё проверено на эмуляторе API 37 против всего бэкенда из compose.

CP6 (начало): ml-service (T-601) — FastAPI + ONNX Runtime, модель-ориентир — логистическая регрессия на признаках ResNet-50 (ML-03), экспорт в ONNX с проверкой эквивалентности; в compose (профиль `apps`, модель монтируется с ПК). core (T-602): `POST /category-suggestions` — проверка владельца фото, вызов ml-service за 3 с, при отказе пустой список, решение пользователя записывается в `ml_suggestions`. Проверено на живом стеке: трещина, плесень — верно; отслоение — вторым после скола; без дефекта — пусто; ml-service остановлен — пустой ответ.

CP5: единая точка входа nginx `https://localhost:8443` (T-505: TLS, маршруты ADR-013, заголовки, лимиты частоты и тела); зашифрованные резервные копии баз и бакетов с проверкой восстановления на чистый compose в CI (T-507); веб-приложение на Next.js 16 за nginx со строгой CSP с nonce (T-501): вход и сессия из refresh-cookie (T-502), объекты, помещения, проведение осмотров, дефекты, фото (T-503), статистика, сравнение, PDF-отчёты (T-504). Живой Playwright-тест веба против compose проходит весь путь от регистрации до скачивания PDF.

## Открытые вопросы и проблемы

| Вопрос | Статус |
|---|---|
| Docker не установлен у владельца проекта | Решено: Docker Desktop 29.9, compose проверен локально |
| Окружение Claude не имеет доступа к Maven Central, npm, PyPI, Go proxy и Docker Hub | Решено: Claude работает локально у владельца, сборки и тесты запускаются до пуша |
| На Windows (`core.autocrlf=true`) shell-скрипты выгружаются с CRLF и не работают в контейнерах | Исправлено в `platform` (#11, `.gitattributes`); в остальные репозитории `.gitattributes` добавляется их ближайшим PR |
| Порт 5432 на ПК владельца занят локальным PostgreSQL | Решено: переменная `POSTGRES_PORT` (#11) |
| Android SDK не установлен у владельца | Решено: Android Studio 2026.2.2, SDK API 37, эмулятор `Medium_Phone` |
| Dependency graph был выключен в android, media-service, report-service, web (Dependency review падал) | Решено: включён владельцем во всех репозиториях |
| MinIO переведён в архив (2026) | Решено: ADR-024, SeaweedFS |
| В каждом репозитории есть начальный коммит с README — будет заменён в первом PR каждого репозитория | Принято к сведению |
| Эмулятор, запущенный из консоли с `HTTP_PROXY` владельца (локальный прокси), отправлял HTTP приложения через прокси — запросы к 10.0.2.2 обрывались | Решено: эмулятор запускается без переменных прокси (на код не влияет) |
| После перезапуска core media-service отвечала `401`: временный ключ JWT менялся, а `kid` — нет | Исправлено: core-service#14, `kid` временного ключа — отпечаток RFC 7638 |
