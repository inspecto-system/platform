# ML-компонент Inspecto

> Статус: CP6, выполнен аудит данных (ML-01, раздел 3); обучения ещё не было. Все метрики в этом документе — только из реальных запусков, с указанием скрипта, версии данных, seed и даты. Планируемое и полученное явно разделяются.

## 1. Задача

**Классификация типа дефекта по фотографии** (ADR-016): по снимку дефекта система предлагает пользователю три наиболее вероятные системные категории. Пользователь подтверждает или выбирает другую — ML не принимает решений за пользователя.

Почему это полезно системе: ускоряет регистрацию дефекта на объекте (меньше нажатий), унифицирует категории между инспекторами, даёт данные для статистики. Почему это ценно для работы: transfer learning, сравнение архитектур CNN и ViT, анализ переноса с открытых данных на реальные фото квартир, измерение полезности подсказок в эксплуатации.

## 2. Рассмотренные направления

| Вариант | Данные | Сложность | Ценность | Решение |
|---|---|---|---|---|
| A. Классификация типа дефекта по фото | Открытые наборы (раздел 3) + собственный тест-набор | Средняя | Высокая | **Основной** |
| B. Бинарная классификация «трещина / нет» | SDNET2018 | Низкая | Низкая (хорошо изученная задача) | Вспомогательный набор |
| C. Фасадные дефекты | FBD | Средняя | Средняя (другой домен) | Проверка обобщения |
| D. Сопоставление фото одного дефекта между осмотрами (эмбеддинги) | Собственные пары фото | Средняя | Высокая | Этап расширения |
| E. Оценка серьёзности по фото | Размеченных данных нет, разметка субъективна | Высокая | Сомнительная | Отклонён |
| F. OCR документов | Готовые движки | Низкая | Низкая (интеграция, а не ML-разработка) | Отклонён |

### 3.4. Между наборами

Точных копий между наборами нет. Почти одинаковых кадров — 3 группы (19 лишних копий): это почти однотонные снимки стен BD3 и покрытий SDNET2018 без деталей, а не одни и те же фотографии.

### 3.5. Что следует для разбиения (ML-03)

1. Из каждой группы точных копий внутри класса остаётся одна.
2. Файлы с противоречивой разметкой (одна копия в двух классах) исключаются целиком.
3. Почти одинаковые кадры попадают в одну и ту же часть разбиения (группировка по найденным группам).
4. Разбиение FBD авторов не используется (в нём утечка) — набор разбивается заново по тем же правилам.

### 3.6. Собственный тестовый набор Inspecto (ML-06)

Фотографии реальных дефектов отделки квартир снимает автор; набор используется **только для итоговой оценки** (ML-07) — не для обучения, не для подбора порога и гиперпараметров, — и хранится только на ПК автора (`ml/data/own/`, в git и облако не попадает).

**Что снимать.** 100–300 фотографий:

| Группа | Сколько | Зачем |
|---|---|---|
| Категории, которые модель подсказывает: `CRACK`, `PEELING`, `STAIN`, `MOLD`, `SPALLING` | по 15–40 каждой | Главная оценка: macro-F1, top-3 |
| Остальные категории Inspecto (обои, плитка, напольное покрытие, окна, двери, неровности, сантехника, электрика) | 20–60 всего, сколько встретится | Проверка, что модель не даёт уверенных неверных подсказок (§8) |
| Отделка без дефекта (стены, потолок, пол) | 20–40 | Доля ложных подсказок на чистых поверхностях |

**Как снимать.** Телефон, обычная камера (без фильтров и «улучшений»); 0,5–1,5 м от поверхности; дефект в центре кадра и занимает заметную его часть; один дефект на кадре; разное освещение (дневной свет, лампы) — как на реальном осмотре. Одного дефекта — не больше трёх кадров (они попадут в одну группу и считаются вместе). В кадр не попадают люди, документы, номера квартир и домов, вид из окна с узнаваемыми местами; снимать только там, где автор имеет право (своя квартира, с разрешения владельцев).

**Как складывать.** Каталог `ml/data/own/photos/`, имена файлов любые; рядом `ml/data/own/labels.csv` (UTF-8) по шаблону:

| Столбец | Пример | Описание |
|---|---|---|
| `file` | `IMG_0412.jpg` | Имя файла |
| `category` | `CRACK` | Код категории Inspecto (§3.7, 14 системных) или `NO_DEFECT` |
| `group` | `kitchen-wall-1` | Один и тот же дефект на нескольких кадрах — одно значение |
| `doubtful` | `yes` / `no` | Автор не уверен в категории |
| `comment` | `трещина по шву гипсокартона` | Необязательно |

**Разметка.** Категорию автор ставит по названиям системных категорий Inspecto, не глядя на подсказки модели (их ещё нет: набор оценивается один раз). Сомнительные случаи — `doubtful = yes`; в результатах они показываются отдельно. Через неделю 30 случайных фото размечаются повторно, не глядя на первую разметку, — совпадение двух разметок показывает, насколько однозначна сама задача.

**Перед оценкой** скрипт ML-07 проверяет таблицу (каждый файл размечен, коды существуют), удаляет EXIF (в нём бывают координаты) и не копирует фото никуда, кроме `ml/data/`. Результаты публикуются только числами и обезличенными примерами ошибок без узнаваемых деталей.

## 4. Методика эксперимента

1. **Аудит данных** (ML-01): лицензии, распределение классов, дубликаты (перцептивный хеш), разрешение, примеры каждого класса.
2. **Разбиение** (ML-03): train/val/test со стратификацией по классам, фиксированный seed; проверка утечки почти одинаковых кадров одной сцены между выборками (группировка по хешу/источнику).
3. **Baseline:** мажоритарный класс; логистическая регрессия на замороженных признаках ResNet-50 (ImageNet).
4. **Дообучение CNN** (ML-04): EfficientNet-B0 и/или ConvNeXt-Tiny; аугментации (повороты, отражения, яркость/контраст, кадрирование), взвешивание классов или сбалансированная выборка.
5. **Дообучение ViT** (ML-05): DeiT-Small / ViT-S/16 с теми же данными и бюджетом обучения.
6. **Выбор модели** по macro-F1 на val; итоговая оценка один раз на test и на собственном наборе.
7. **Анализ ошибок** (ML-07): матрица ошибок, примеры ложных срабатываний, анализ по условиям съёмки.
8. **Экспорт** в ONNX и проверка эквивалентности с PyTorch (расхождение вероятностей < 1e-3, совпадение top-1 на всём test).

Вычисления — локально на CPU ПК владельца в контейнере `python:3.12-slim` (ADR-027): облегчённая схема — небольшие модели, входное разрешение 224, сначала признаки замороженной сети, затем дообучение последних слоёв. Код — пакет `inspecto_ml` в репозитории `ml`; каждый запуск сохраняет конфигурацию, seed, отпечатки данных и метрики.

## 5. Метрики

| Метрика | Зачем |
|---|---|
| Macro-F1 (основная) | Классы несбалансированы; все классы одинаково важны |
| Precision и Recall по классам | Какие дефекты модель путает или пропускает |
| Матрица ошибок | Структура ошибок |
| Accuracy | Для сравнения с литературой |
| Top-3 accuracy | Интерфейс показывает три подсказки |
| Время инференса на CPU | Применимость в ml-service |
| Доля принятых подсказок в эксплуатации (`ml_suggestions.decision`) | Полезность для пользователя |

## 6. Интеграция

- ml-service: FastAPI + ONNX Runtime (CPU), endpoint `POST /internal/v1/classify` → top-3 кодов категорий с вероятностями и версия модели.
- Предобработка идентична обучению (размер, нормализация); фиксируется в конфигурации модели рядом с ONNX-файлом.
- Порог уверенности: если максимальная вероятность ниже порога (подбирается на val), подсказка не показывается.
- Подробная схема — архитектурный документ, раздел «Взаимодействие с ML-сервисом».

Затем при расписании 1 + 2 эпохи EfficientNet-B0 была недообучена (0,51 → 0,75 → 0,80 на проверке, 0,773 на тесте); расписание увеличено до 2 + 6. Один запуск был прерван выключением ПК и повторён целиком.

## 8. Ограничения (будут дополнены по результатам)

- Домен открытых наборов (бетон, фасады) отличается от типичных дефектов отделки квартир.
- Для 9 из 14 категорий (`UNEVEN_SURFACE`, `WALLPAPER`, `TILE`, `FLOOR_COVERING`, `WINDOW`, `DOOR`, `PLUMBING_LEAK`, `ELECTRICAL_FAULT`, `OTHER`) открытых данных нет, и модель их не подсказывает (§3.7). Чтобы на таких фото не появлялась уверенная неверная подсказка, служит порог уверенности (§6); насколько он справляется, измеряется на собственном наборе, где эти категории есть.
- Небольшой собственный тестовый набор даёт широкие доверительные интервалы; они будут указываться.
- Модель классифицирует изображение целиком и не локализует дефект.
