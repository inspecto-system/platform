# ML-компонент Inspecto

> Статус: план исследования (CP0). Экспериментов ещё не проводилось. Все метрики, которые появятся в этом документе, — только из реальных запусков, с указанием ноутбука, версии данных, seed и даты. Планируемое и полученное явно разделяются.

## 1. Задача

**Классификация типа дефекта по фотографии** (ADR-016): по снимку дефекта система предлагает пользователю три наиболее вероятные системные категории. Пользователь подтверждает или выбирает другую — ML не принимает решений за пользователя.

Почему это полезно системе: ускоряет регистрацию дефекта на объекте (меньше нажатий), унифицирует категории между инспекторами, даёт данные для статистики. Почему это ценно для работы: transfer learning, сравнение архитектур CNN и ViT, анализ переноса с открытых данных на реальные фото квартир, измерение полезности подсказок в эксплуатации.

### 3.4. Собственный тестовый набор Inspecto

- 100–300 фотографий реальных дефектов отделки квартир, снятых автором (ML-06).
- Разметка по таксономии Inspecto по письменному протоколу; спорные случаи помечаются.
- Используется **только для итоговой оценки**, не для обучения и подбора гиперпараметров.
- Без персональных данных: в кадр не попадают люди, документы, номера квартир; EXIF удаляется.

### 3.5. Предварительное соответствие классов

Уточняется в ML-02 вместе с системными категориями core-service.

| Класс BD3 | Системная категория Inspecto (код) |
|---|---|
| major crack, minor crack | `CRACK` (трещина); различие ширины может стать признаком серьёзности в будущем |
| peeling | `PEELING` (отслоение покрытия) |
| stain | `STAIN` (пятно, следы протечки) |
| algae | `MOLD` (плесень, биопоражение) — проверить визуальную близость на интерьерных фото |
| spalling | `SPALLING` (скол, разрушение поверхности) |
| normal | Нет дефекта (подсказка не показывается) |

Риск: дефекты отделки, характерные для приёмки квартир (обои, ламинат, плитка, сантехника), в открытых наборах представлены слабо. Это ограничение фиксируется, а его влияние измеряется на собственном наборе.

## 4. Методика эксперимента

1. **Аудит данных** (ML-01): лицензии, распределение классов, дубликаты (перцептивный хеш), разрешение, примеры каждого класса.
2. **Разбиение** (ML-03): train/val/test со стратификацией по классам, фиксированный seed; проверка утечки почти одинаковых кадров одной сцены между выборками (группировка по хешу/источнику).
3. **Baseline:** мажоритарный класс; логистическая регрессия на замороженных признаках ResNet-50 (ImageNet).
4. **Дообучение CNN** (ML-04): EfficientNet-B0 и/или ConvNeXt-Tiny; аугментации (повороты, отражения, яркость/контраст, кадрирование), взвешивание классов или сбалансированная выборка.
5. **Дообучение ViT** (ML-05): DeiT-Small / ViT-S/16 с теми же данными и бюджетом обучения.
6. **Выбор модели** по macro-F1 на val; итоговая оценка один раз на test и на собственном наборе.
7. **Анализ ошибок** (ML-07): матрица ошибок, примеры ложных срабатываний, анализ по условиям съёмки.
8. **Экспорт** в ONNX и проверка эквивалентности с PyTorch (расхождение вероятностей < 1e-3, совпадение top-1 на всём test).

Вычисления — Google Colab (GPU); ноутбуки хранятся в репозитории `ml/notebooks`, выполненные версии с выводами — артефакты эксперимента.

## 5. Метрики

| Метрика | Зачем |
|---|---|
| Macro-F1 (основная) | Классы несбалансированы; все классы одинаково важны |
| Precision и Recall по классам | Какие дефекты модель путает или пропускает |
| Матрица ошибок | Структура ошибок |
| Accuracy | Для сравнения с литературой |
| Top-3 accuracy | Интерфейс показывает три подсказки |
| Время инференса на CPU | Применимость в ml-service |
| Доля принятых подсказок в эксплуатации (`ml_suggestions.decision`) | Полезность для пользователя |

## 6. Интеграция

- ml-service: FastAPI + ONNX Runtime (CPU), endpoint `POST /internal/v1/classify` → top-3 кодов категорий с вероятностями и версия модели.
- Предобработка идентична обучению (размер, нормализация); фиксируется в конфигурации модели рядом с ONNX-файлом.
- Порог уверенности: если максимальная вероятность ниже порога (подбирается на val), подсказка не показывается.
- Подробная схема — архитектурный документ, раздел «Взаимодействие с ML-сервисом».

## 8. Ограничения (будут дополнены по результатам)

- Домен открытых наборов (бетон, фасады) отличается от типичных дефектов отделки квартир.

- Модель классифицирует изображение целиком и не локализует дефект.
